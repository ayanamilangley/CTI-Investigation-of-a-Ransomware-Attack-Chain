# Queries for CAR-2020-05-001 "MiniDump of LSASS"

Source of the analytic: https://car.mitre.org/analytics/CAR-2020-05-001/

Idea: Sysmon EventID 10 (a process opened another process), the target is `lsass.exe`, and the
`CallTrace` (list of modules in the call stack) contains `dbghelp.dll` or `dbgcore.dll`. These
libraries are used when a program dumps memory with the Windows function `MiniDumpWriteDump`.

## Original query from CAR (Splunk, Sysmon native)

```
index=__your_sysmon_index__ EventCode=10 TargetImage="C:\\windows\\system32\\lsass.exe" (CallTrace="*dbghelp.dll*" OR CallTrace="*dbgcore.dll*")| table _time host SourceProcessId SourceImage
```

## Our version for Kibana (KQL)

Index / data view: `blackbasta-car` (load it with [`../elk/load_to_elk.py`](../elk/load_to_elk.py)).
Time range in Discover: **Last 10 years**. Write values in lowercase.

```
EventID:10 and Channel:"microsoft-windows-sysmon/operational"
  and TargetImage:*lsass.exe
  and (CallTrace:*dbghelp.dll* or CallTrace:*dbgcore.dll*)
```

What we changed: `TargetImage:*lsass.exe` instead of the full path `C:\windows\system32\lsass.exe`,
so the query does not depend on how the path is written. The logic is the same.

Expected: **1 hit**, `WORKSTATION5`, source `rundll32.exe`, `GrantedAccess` `0x1fffff`, and `dbgcore.dll` in the CallTrace.

Useful columns for Discover: `Hostname`, `SourceImage`, `TargetImage`, `GrantedAccess`, `CallTrace`, `dataset`.

## Comparison query (our Week 5 H3 filter, same index)

```
EventID:10 and TargetImage:*lsass.exe
  and GrantedAccess:(0x1fffff or 0x1010 or 0x1410 or 0x143a or 0x1438)
  and not SourceImage:(*msmpeng.exe or *svchost.exe or *wmiprvse.exe or *csrss.exe or *wininit.exe or *services.exe)
```

Expected: **2 hits** (`rundll32.exe` with `0x1fffff` and with `0x1410`). The second one has no `dbgcore.dll`
or `dbghelp.dll` in its CallTrace, so the CAR query does not find it.
